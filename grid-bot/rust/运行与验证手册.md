# Decibel Grid Bot：运行、验证与上线手册

本手册对应 `grid-bot/rust` 的 Rust TUI/CLI 网格工具。目标是让操作者按**只读验证 → Shadow → Testnet 小额 Live → Mainnet 只读 → Mainnet 小额 Live**的顺序推进，避免直接把未经验证的策略投入真实资金。

> 本工具是风险交易软件，不保证利润。网格策略会积累库存或合约敞口；价格单边运动、流动性下降、资金费、网络故障与交易所 API 行为均可能造成损失。

## 1. 当前状态：已验证与未验证范围

| 范围 | 状态 | 说明 |

## 2. 架构与安全原则

```text
Market/API snapshot
      ↓
Pure grid planner + precision rules
      ↓
Spot PFS fitting / Perp margin estimate
      ↓
Desired-vs-actual reconciliation
      ↓
shadow / doctor / reconcile / guarded live bulk
      ↓
append-only journal + TUI / CLI observability
```

核心原则：

1. **交易所是订单事实来源。** 本地 journal 用于审计，不应覆盖交易所状态。
2. **Spot 只用 PFS。** 不自动做 Cross/CBS → PFS 划转，不自动补币，不等待 POST_ONLY 成交。
3. **先 reconciliation，后执行。** 期望网格与交易所订单不一致时必须可见。
4. **Fail closed。** Decibel bulk API 当前没有可用于订单归属的 client order ID；市场内只要存在任何订单，Live CLI 不会执行 bulk replacement。
5. **先 Testnet，后 Mainnet。** Mainnet 最低前置是 read-only `doctor` 和 bounded `shadow` 均成功。
6. **私钥绝不进入普通日志或文档。** CLI `--help` 已隐藏 API key、私钥和 subaccount 环境变量当前值。

## 3. 本地配置

进入目录：

```bash
cd grid-bot/rust
cp .env.example .env
chmod 600 .env
```

### Testnet 最小只读配置

```dotenv
NETWORK=testnet
DECIBEL_API_KEY=<testnet REST API key>
SUBACCOUNT_ADDRESS=<testnet subaccount>
```

`doctor`、`status`、`reconcile`、`shadow` 不需要 `APTOS_PRIVATE_KEY`。

### Testnet Live 配置

只有在准备测试真实 bulk 提交时才增加：

```dotenv
APTOS_PRIVATE_KEY=<testnet signer private key>
```

确保 signer 对该 subaccount 有对应 Spot 或 Perp 交易权限，并有足够 APT 支付 gas。

### Mainnet 配置

Mainnet key 与 Testnet key 必须分开。不要仅把 `NETWORK` 改为 `mainnet` 后复用 Testnet key。

```dotenv
NETWORK=mainnet
DECIBEL_API_KEY=<authorized mainnet REST API key>
SUBACCOUNT_ADDRESS=<matching mainnet subaccount>
```

如果 Mainnet `doctor` 返回 `401 Unauthorized`，通常表示 key 无效、权限不足或属于 Testnet；不要反复重试，先在 Decibel Dashboard 重新核实网络与权限。

## 4. 命令速查

| 命令 | 是否签名交易 | 是否改变交易所状态 | 用途 |
|---|---:|---:|---|
| `check-key` | 否 | 否 | REST/WS API key 验证 |
| `status` | 否 | 否 | 一次性市场、计划、账户与成交快照 |
| `doctor` | 否 | 否 | API、规则、资金、保证金、reconciliation 前置检查 |
| `reconcile` | 否 | 否 | 期望档位与开放订单 drift 检查 |
| `shadow` | 否 | 否 | 持续读取、reconcile、journal 审计 |
| `run` | 否 | 否 | 持续 CLI 监控 |
| `run -e` | 是 | 是 | guarded bulk 执行，必须谨慎使用 |
| `tui` / `preview` | 仅 TUI 明确执行动作时 | 视操作而定 | 交互配置、预览、监控 |

## 5. Testnet 验证流程

### 5.1 构建与静态检查

```bash
cargo fmt --check
cargo test
cargo clippy --all-targets --all-features -- -D warnings
cargo build
```

预期：命令都退出 `0`。

### 5.2 API key 检查

```bash
cargo run -- check-key --network testnet
```

预期：REST 与 WebSocket 都接受 API key。

### 5.3 Spot 只读 doctor

```bash
cargo run -- doctor \
  --network testnet \
  --product spot \
  --market APT/USDC \
  --range-percent 5 \
  --grid-count 20 \
  --total-budget 500
```

检查输出中的：

- `tick`、`lot`、`min_size`；
- `PFS` 的 base/quote 可用余额；
- `plan` 中 bid/ask 数量；
- `reconciliation` 中 `unmanaged=0`；
- 最后一行必须为 `read-only checks passed`。

例如 PFS USDC 为 0 时，Spot 计划会安全地变为仅卖单网格，这是正确行为；不是程序故障。

### 5.4 Perp 只读 doctor

```bash
cargo run -- doctor \
  --network testnet \
  --product perp \
  --market BTC/USD \
  --range-percent 5 \
  --grid-count 20 \
  --total-budget 500
```

检查：

- `estimated` margin 小于 `available` margin；
- 所有档位满足 tick、lot、最小下单量；
- `unmanaged=0`；
- 最后一行是只读成功信息。

### 5.5 Bounded Shadow

Bounded Shadow 在指定的成功 reconciliation 次数后正常退出，适合自动化验收：

```bash
# Spot：不签名、不提交、不取消
cargo run -- shadow \
  --network testnet \
  --product spot \
  --market APT/USDC \
  --range-percent 5 \
  --grid-count 20 \
  --total-budget 500 \
  --shadow-cycles 2

# Perp：不签名、不提交、不取消
cargo run -- shadow \
  --network testnet \
  --product perp \
  --market BTC/USD \
  --range-percent 5 \
  --grid-count 20 \
  --total-budget 500 \
  --shadow-cycles 2
```

预期：

```text
SHADOW RECONCILE — ...
Shadow cycle limit reached. No orders were placed or cancelled.
```

临时空盘口/无价格时可能出现 `shadow refresh failed`；Shadow 会跳过该轮继续读取，且绝不会因此发送交易。

## 6. Journal 审计

默认位置：

```text
macOS: ~/Library/Application Support/decibel-grid/runs/<run_id>/
```

受限容器或 CI 可覆盖：

```bash
DECIBEL_GRID_DATA_DIR=/path/to/writable \
  cargo run -- shadow ...
```

每个 run 目录主要包含：

```text
events.jsonl    # append-only event stream
state.json      # 最新状态快照（Live/需要 state 的运行）
```

Journal 的保护措施：

- `RunStart` 不保存原始 subaccount，仅保存 SHA3-256 指纹；
- 每个 event 写入后调用 `sync_all()`；
- state 使用临时文件、同步、rename、父目录同步；
- Shadow 不会产生 `BulkOrderSubmitted` 或 `BulkOrderFailed` 事件。

## 7. TUI 使用

TUI 主要标签：

| 标签 | 用途 |
|---|---|
| Configure | 设置网络、产品、市场、范围、数量、预算、凭据/profile |
| Preview | 观察理论网格、费用后利润预览、执行按钮 |
| Monitor | 市场/账户/成交监控与 reconciliation 状态 |

Monitor 摘要中的 reconciliation 行：

```text
RECONCILE  Matched N  Missing N  Unmanaged N
```

解释：

- `Matched`：开放订单与期望档位匹配；
- `Missing`：期望存在但实际未挂；
- `Unmanaged`：开放订单无法安全归属给当前策略；
- `BULK BLOCKED: existing orders`：安全策略会阻断 bulk replacement。

TUI 里的 `Filled` 格子来自近期 trade history，只是显示提示；CLI/Shadow/Live 在执行前会重新构建纯 executable plan，历史同价成交不会永久跳过后续档位。

## 8. Testnet Live bulk 提交前检查清单

以下步骤尚未由本项目实际验收。只有你明确决定进行小额 Testnet Live 时才执行：

1. 运行 Spot/Perp `doctor`，确认退出码 0；
2. 运行 bounded `shadow --shadow-cycles 2`，确认没有未知订单；
3. 确认市场内没有任何手工订单、旧 bot 订单或其他策略订单；
4. 确认 signer 已获对应交易权限；
5. 确认 signer 有足够 APT gas；
6. 设置极小预算和较少档位；
7. 运行 `run -e`，观察 transaction hash 与 Decibel open orders；
8. 再次运行 `reconcile` 与 `doctor`，检查落地订单和资金锁定。

示例（仅在完成以上人工确认后）：

```bash
cargo run -- run -e \
  --network testnet \
  --product spot \
  --market APT/USDC \
  --range-percent 2 \
  --grid-count 2 \
  --total-budget 50 \
  --refresh-seconds 20
```

> `run -e` 是真实链上行为，不要复制到 Mainnet。当前 bulk API 没有 client order ID；如果市场存在任何订单，程序会 fail-closed 并拒绝自动替换。

## 9. Mainnet 推进顺序

1. 配置独立的 Mainnet REST API key 与 Mainnet subaccount；
2. `check-key --network mainnet`；
3. Spot/Perp `doctor --network mainnet`；
4. Spot/Perp bounded `shadow --network mainnet --shadow-cycles 2`；
5. 审核 journal、账户、市场内是否有未知订单；
6. 只有经人工风险批准后，才进行极小规模 Mainnet `run -e`。

Mainnet Live 额外要求：

```bash
--confirm-mainnet MAINNET
```

没有此确认词，`run -e --network mainnet` 必须拒绝执行。

## 10. 已下载研究对象与设计结论

已下载源码（默认在本仓库的已忽略目录 `.atlas/research/`）：

| 项目 | 研究重点 | 对本工具的影响 |
|---|---|---|
| Hummingbot V2 | Controller/Executor、GridExecutor 状态机、止盈/止损、持久化 | 策略规划与交易执行分层；订单生命周期应独立于 UI |
| Passivbot | Wallet Exposure Limit、equity hard stop、重启风控 | Perp 必须有总敞口、损失、强平距离等独立风险层 |
| Freqtrade | typed config、dry-run、配置优先级、回测 | CLI-first、环境隔离、可解析运行配置 |
| OctoBot | grid automation、paper trading、backtesting | Shadow/Paper 应先于真实资金运行 |

后续建议按优先级：

1. Testnet 小额真实 bulk lifecycle 验收；
2. Mainnet read-only doctor/shadow；
3. 状态恢复协议与订单归属能力确认；
4. 订单簿回放/历史回测与滑点、费用、资金费模型；
5. 组合风险层（Spot inventory + Perp delta + funding + liquidation buffer）。
